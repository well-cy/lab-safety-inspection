## 三、`ppe_public.zip` 逐项评估

它其实是**三个数据集的打包**（内含 `公开PPE数据集下载与核验报告.md`，写得很规范，可复用）。

### 3.1 CPPE-5 → 已是"老熟人"，**不新增**

- 报告口径：train 1,000 张 / 4,491 框；test 29 张 / 207 框。5 类 = Gloves / Coverall / Mask / Face_Shield / Goggles。
- **本项目早已入库**：`data/raw/cppe5/` + `data/lab_ppe` 里 **358 张 `cppe5_*`** 图
  （person 749 / mask 551 / gloves 581 / lab_coat 1 / goggles 184），并且已经过 **p0_c…p0_i 共 7 轮人工审核补标**
  （这也是为什么要审核队列：CPPE-5 原标注只含 mask / gloves / goggles / coverall / face_shield，person 全靠补）。
- E4 早有拍板：**「整包不入库，挂起为 mask 应急备胎」**。
- 本次包里唯一新增价值是 `CPPE5_original/`（COCO 原始副本 + parquet）——**留档追溯用**，不产生训练增量。
- ⚠️ **许可**：HF 卡片 `license: unknown`。若成果要公开发布，需先确认许可（报告已提示）。

### 3.2 PPE_Detection → 是**新的** Roboflow project，但域不合、优先级低

**先厘清三条容易混淆的来源线**（我逐份读了各自的 `data.yaml` 核实，不要混为一谈）：

| 名称 | Roboflow project | 类数 | 与本包的关系 |
|---|---|---|---|
| **PPE_Detection**（本包 / PPE.zip） | `tanish-y7iqo/ppe-detection_data-adcya` **v3** | 6 类：Gloves/Vest/goggles/helmet/mask/safety_shoe | ← **本次新下载** |
| 库内 `data/raw/ppedetect` | `saba/ppedetection` **v7** | 5 类：Coverall/Face_Shield/Gloves/Goggles/Mask | 不同 project，勿混 |
| 库内 `data/raw/dataset1` | `vitor-ferraz-marini/lab_ppe-g8hja` **v1** | 13 类（含 Lab coat） | 底座来源 |

- 结论修正：**PPE_Detection 与库内 `ppedetect` 不是同一个 project**，是**新的独立来源**——
  所以它**不像我最初判断的那样"已同源否决"**，原则上可以走审计流程。
  已做**泄漏抽样验证**：随机抽 400 张 PPE.zip 图片算 MD5，与库内全部 2,231 张图片 MD5 索引比对，
  **命中 0 张**（完全无同图）→ 确认**与现有训练库零重叠**，不是既有数据的派生副本。（完整入库前仍应跑正式三向审计。）
- 但**实际收益很低**，理由三条：
  1. **无 lab_coat、无 person**——正是我们最缺的两类，它一个都不补；
  2. 类目与库内已有高度重叠：Gloves / goggles / mask 我们已有 SH17 + CPPE-5 + 既有批次支撑；
     Vest / helmet / safety_shoe 本项目 **5 类根本不要**；
  3. 报告自陈 + 既往记录互相印证的**质量/域问题**：空标签 3,756 张（31%）、
     goggles 疑似混入普通眼镜、少量 shutterstock 水印、**工地/工业域**（与实验室域差异大）。
- 另需注意：库内 `data/raw/ppedetect`（saba v7）在 2026-09-23 审计中**362/364 与 dataset1 MD5 级重复 → 否决**；
  同批 `epidetect/ppe-wlllw` 因**第 4 关「标注一致性」崩坏**（多副本 73% 手套标注冲突、相邻帧翻转率 38–60%）**也否决**，
  并由此**结案「外部引入线就此收束」**（E4 第 327–335 行）。PPE_Detection 是**结案之后**新出现的候选，
  若要启用，须**重开第 4 关**（标注一致性：同源副本一致率 / 相邻帧翻转率 / 类别域匹配）。
- **裁决**：
  - 若将来确需补 mask / goggles / gloves 的多样性，**优先 CPPE-5（域更近、已入库可复用）**，其次是本包；
  - 鉴于当前优先级是 lab_coat、且外部线已结案，**不建议本轮投入 PPE_Detection**；
  - `PPE.zip` 与 `ppe_public` 内的 `PPE_Detection_original`：两者 `data.yaml` **逐字节相同**（同 workspace/project/version 3），
    **确认是同一份数据的两个副本** → 留一份归档即可，**别重复处理 668 MB**。

### 3.3 LVIS lab_coat 子集 → **留作测试/回归，不入训练**

- 报告口径（含一处**重要更正**）：LVIS 官方 `category_id = 620`（不是 Ultralytics 文档里的 619，619 是 koala）；
  **全集只有 10 张图 / 46 框**（train 7/42、val 3/4）。
- 标注质量高（确是白大褂，无错标），但场景多为**农牧展会、医院病房、街头**，**仅 1 张是真实验室**。
- 46 框远不够训练。**建议当"白大褂域差异"的定性验证 / 回归样本**（类似 `data/test` 的角色），这与 dataset2 只读红线**不冲突**。
- 与组长微信口径一致（"先不要拿来训练，建议当测试/回归样本"）。

## 四、`protective-equipment-detection/`（待确认来源）

- 实际内容：`train.zip`（904 MB）+ `valid.zip`（1.13 GB）+ `test.zip`（245 MB），共约 **2.3 GB**，**未解压**。
- 组长描述：含 goggles / mask / glove / suit 及对应 `no_mask` / `no_goggles` / `no_glove` / `no-suit` 等类别，Manufacturing / 工业制造场景。
- ⚠️ **必须先确认来源**再决定，原因：
  1. 需核对它的 Roboflow project / workspace / version（对照上表三条已知线），判断是否与
     `tanish-y7iqo/ppe-detection_data-adcya`（本批 PPE_Detection）、`saba/ppedetection`（库内 ppedetect）、
     `vitor-ferraz-marini/lab_ppe-g8hja`（dataset1）中的任何一条**重合或派生**；
  2. 若确为**独立来源**，才值得重开第 4 关（标注一致性）走审计；
  3. `no_*` 类**不能简单映射**：本项目 5 类是"存在的物体"（person/mask/gloves/lab_coat/goggles），
     没有"未佩戴"类；`no_*` 只能当**负样本语境**或直接丢弃，不能当正类标注。
  4. `suit` **不能映射成 lab_coat**（这一点组长已强调；E4 里 Coverall→lab_coat 是**用户专门拍板的特例**，
     理由是为连体防护服形态，**不是**通用规则，不可外推）。
- **行动**：先给我（或自己）跑一次来源三向审计 + 定级：
  ```bash
  # 解压到 data/raw/ 下新目录后
  .venv/Scripts/python.exe tools/dedup_new_dataset.py --src data/raw/<新目录> --name <名> \
      --refs dataset1,dataset2,labcoat_si
  ```
  同源或第 4 关不过 → 一并否决；确为独立来源且域可接受 → 再谈筛选 mask / goggles / glove。

## 五、`e58z9vu3fcusg7wzjk91n.zip`（1.3K lab coat 分类图）

- 实测：**1,308 条目 / 1,299 张图**，顶层 `images.cv_e58z9vu3fcusg7wzjk91n/`，**0 个 txt、1 个 json** → 确认是**分类数据集，无 bbox**。
- 组长说明：原始分辨率、彩色、无数据增强；不是 YOLO 检测集，**不能直接混训**。
- **这是当前唯一"对症 lab_coat"的新素材**，但要把"分类图"变成"检测集"必须补三步：
  1. **筛**：先剔除"实验室/科研/医疗操作"场景红线之外的（电商商品图、生活照、纯衣物平铺、低质量/糊图）；
  2. **标**：人工画 `lab_coat` 检测框（可先用现有模型预标注再校正，但权重 `.pt` 被 `.gitignore` 排除，需向组长索取）；
  3. **合**：按来源命名前缀（如 `lc13_`）+ 走 `data/_rejected/<tag>_<日期>/` 只移不删 + 落库前 tar 备份的既有口径。
- 规模换算：1,299 张里若筛出 300–500 张可用，人工标框是本项目**单批最大的一次标注量**，
