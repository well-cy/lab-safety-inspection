# 系统架构与模块说明

## 1. 系统架构

```
输入层        图片上传 / MP4 视频上传（第二阶段：摄像头）
                │
视频处理层    OpenCV（读帧、写标注视频、截图）
                │
AI 检测层     SH17 YOLOv8s（ultralytics）→ 类别映射 → 6 业务类别
                │
目标关联层    Person-PPE Matching（中心点包含 + 最近距离兜底）
                │
区域判断      ROI 矩形区域（归一化坐标，数据库可配置）
                │
规则引擎      SafetyRuleEngine（区域 PPE 要求 → 违规类型 + 严重程度）
                │
违规事件      ViolationEvent（截图、冷却去重）
                │
数据库        SQLite（laboratories / areas / safety_rules /
              detection_records / violation_events）
                │
后端          FastAPI（REST API + 静态文件）
                │
前端          HTML/JS/CSS + ECharts（Dashboard / 巡检 / 违规记录 / 统计 / 设置）
```

## 2. 模块说明

### ai/ — AI 检测层
- `detector.py`：PPEDetector 封装 YOLO；Detection 统一数据结构；
  CLASS_ALIAS 完成原始类别→业务类别映射（不支持的类别过滤掉）。
- `ppe_matcher.py`：match_person_ppe()。对每个 PPE 框：
  ① 若中心点落入某 person 框内则归属之（重叠时选面积更小的框）；
  ② 否则归属最近人员，但距离须小于该人员框对角线的 0.5 倍。
  输出 PersonState（每人绑定自己的 PPE 集合）。
- `roi.py`：AreaROI（归一化矩形）+ locate_person()。人员框中心点
  落入区域即判定在该区域；不在任何区域 → 普通区域（不评估）。

### rule_engine/ — 规则引擎
- `engine.py`：SafetyRuleEngine.evaluate()。区域内人员按该区域
  required_ppe 检查缺失项：缺 1 种 → 一般违规；缺 ≥2 种 → 严重违规；
  不缺 → 正常。输出 ViolationEvent（含 person_id/区域/违规类型/严重程度/
  时间戳/截图路径）。规则从数据库读取，不硬编码。

### video/ — 视频处理
- `processor.py`：
  - InspectionPipeline.analyze_frame()：单帧完整管线；
  - process_image()：图片模式（含违规截图保存）；
  - process_video()：视频模式。每 stride 帧做一次推理（中间帧复用结果），
    标注每帧；同一组违规每 10 秒截图一次（冷却去重）。

### backend/ — Web 系统
- `main.py`：FastAPI 应用与全部路由（详见 API 说明文档）。
- `database.py`：SQLite 建表/种子数据/查询统计/写入。
- `static/index.html`：单页前端（5 个页签）。

### tests/ — 测试
- `run_tests.py`：T01~T14 用例 + 性能实测，生成 test_report.md。
- `make_test_video.py`：合成演示视频。

## 3. 数据库设计

```
laboratories(id, name, description, created_at)
areas(id, lab_id→laboratories, name, x1, y1, x2, y2, created_at)   -- 归一化矩形
safety_rules(id, area_id→areas, ppe_type, required)  -- 区域要求的 PPE
detection_records(id, lab_id, source_type, source_name, person_count,
                  violation_count, normal_count, process_time_ms, created_at)
violation_events(id, record_id→detection_records, lab_id, area_name,
                 person_id, violation_types, severity, screenshot_path,
                 frame_time, created_at)
```

种子数据：实验室A → 实验操作区（ROI 0.22,0.18,0.88,0.92）
→ 要求 mask + gloves + lab_coat。

## 4. 关键设计决策

1. **不做 tracking**：第一阶段用"每帧独立检测 + 违规冷却去重"替代多目标
   跟踪，person_id 是帧内编号。第二阶段可加 ByteTrack/DeepSORT。
2. **stride 帧复用**：视频每 2 帧推理一次（可配置），标注每帧，兼顾速度
   与流畅。
3. **规则可配置**：区域和 PPE 要求存数据库，通过设置页增删改，演示时
   可现场修改规则立即生效。
4. **SQLite**：零部署成本；表结构兼容后续迁移 MySQL。
