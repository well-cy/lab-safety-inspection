# 基于计算机视觉的实验室安全智能巡检与违规预警系统——项目概述

- **项目类型**：软件工程课程项目
- **团队规模**：5 人
- **技术主线**：计算机视觉（目标检测）+ 实验室安全业务规则 + Web 系统集成
- **文档版本**：v1.1（基于 2026-09-10 仓库实际状态修订：修正接口数量、性能数据、架构表述与模型来源表述）

## 1. 项目背景与需求分析

实验室是高校教学与科研活动的重要场所，实验人员的个人防护装备（PPE）穿戴规范是实验室安全管理的基本要求。目前在多数高校中，这类检查主要依赖安全管理人员的现场巡查，存在明显不足：巡检频率有限，难以持续监督；违规只能在事后被发现；检查尺度受人员经验和状态影响，标准不一；巡检记录难以汇总、统计和追溯。

计算机视觉中的目标检测技术为解决这一问题提供了可行路径：对实验区域的图像或视频自动识别人员及其穿戴的 PPE 物品，结合安全管理业务规则进行判断，即可构建持续运行、自动判断、自动记录的视觉巡检系统。基于这一思路，开发团队提出本项目，围绕"实验操作区域内人员 PPE 穿戴合规性检查"这一具体问题，构建一个能够实际运行和演示的实验室安全智能巡检原型系统。

## 2. 项目目标

本项目希望实现一个覆盖"检测—关联—判断—预警—记录—统计"完整链路的实验室安全智能巡检原型系统：对实验场景图像或视频中的人员进行检测，识别其穿戴的口罩、手套、实验服、护目镜等 PPE 物品，并将其与对应人员关联；支持在画面中划定实验操作区域（ROI）并判断人员是否位于区域内；根据区域配置的安全规则判断缺失了哪些必需 PPE，按缺失数量区分违规严重程度；对违规行为自动生成事件、保存截图并写入数据库；通过 Web 页面提供巡检操作、违规记录查询与数据统计功能。

需要说明的是，本项目定位为"辅助巡检与违规预警"的原型系统，目标是验证技术路线可行性并形成可运行、可演示的完整系统，不追求替代安全管理人员，也不覆盖所有类型的实验室安全风险。

## 3. 项目定位与总体思路

本项目的总体定位是：基于已有开源目标检测模型和公开数据集，进行二次开发、模型优化与系统集成，重点研究如何将计算机视觉检测结果与实验室安全业务规则结合起来，形成完整的"检测—关联—区域判断—规则判断—违规预警—记录统计"业务链路。

本项目不从零训练大型 AI 模型。系统采用的基线模型是基于 SH17 数据集训练的开源 YOLOv8s 权重（由 SH17 数据集发布仓库提供下载），开发团队在其基础上完成了类别映射、业务封装、规则引擎、数据存储与 Web 前端等系统工程工作，并针对实验服识别效果不足的问题，使用公开数据集开展了再训练与对比评估实验。换言之，AI 模型只是系统的一个组成部分，本项目的工作重点在于完整系统的设计、集成与实现：如何定义业务数据结构、如何将检测结果转化为有业务含义的违规事件、如何让整个流程可以实际运行和验证。

## 4. 系统总体功能

当前系统已实现一个单页 Web 应用，包含五个功能页面：

| 模块 | 主要功能 |
| --- | --- |
| 首页 Dashboard | 展示今日检测次数、违规次数、违规率、违规类型分布等指标 |
| 智能巡检 | 上传图片或 MP4 视频进行 PPE 检测，展示带标注的检测结果，视频逐帧处理并回放标注结果 |
| 违规记录 | 按日期、严重程度等条件查询历史违规事件及违规时刻截图 |
| 数据统计 | 按天、按违规类型、按 PPE 类型等维度统计分析并图表展示 |
| 系统设置 | 管理实验室、实验操作区域（ROI）及各区域的必需 PPE 规则（可配置） |

智能巡检页是系统核心入口，检测过程会输出每个人员的 PPE 穿戴评估（穿戴齐全 / 一般违规 / 严重违规），并在违规时自动保存截图。

## 5. 核心业务流程

系统核心业务流程如下，每一步均对应仓库中的具体代码模块：

```
图像 / 视频输入
      ↓  （前端上传，FastAPI 接收）
YOLO 目标检测
      ↓  （ai/detector.py：识别人员与 PPE，映射为业务类别）
人员与 PPE 目标关联
      ↓  （ai/ppe_matcher.py：按空间归属将 PPE 分配给人员）
判断人员是否进入实验操作区域
      ↓  （ai/roi.py：人员中心点是否位于区域矩形内）
获取该区域对应的安全规则
      ↓  （backend/database.py：safety_rules 表）
判断缺失哪些 PPE
      ↓  （rule_engine/engine.py：比对必需与实际穿戴）
根据违规数量判断严重程度
      ↓  （缺 0 项→正常；1 项→一般违规；≥2 项→严重违规）
生成违规事件
      ↓  （时间、人员、区域、缺失 PPE、严重程度）
保存违规截图、写入数据库
      ↓  （outputs/screenshots/；detection_records、violation_events 表）
前端展示、历史记录与数据统计
```

以视频巡检为例：用户上传实验操作视频，视频处理模块（video/processor.py）按固定间隔抽帧，逐帧执行上述流程；出现违规时自动截取当前帧保存并将事件写入数据库，处理完成后前端回放标注视频并列出本次巡检发现的违规事件。

## 6. 系统技术架构

系统采用 B/S 架构，前后端按模块划分并通过 REST API 交互：前端为 FastAPI 后端直接提供的单页静态应用（部署于后端 static 目录），无需独立前端服务器。系统自上而下分为六层：

**前端展示层**：HTML + JavaScript + ECharts 构建的单页应用（backend/static/index.html），负责巡检操作、结果展示与数据可视化，通过 REST API 与后端交互。

**后端业务层**：Python + FastAPI（backend/main.py），提供一组 `/api` 前缀的 REST 接口，覆盖统计、查询、检测与设置业务，并负责向前端提供静态页面资源，组织检测流程并返回 JSON 结果。

**AI 检测层**（ai/detector.py）：封装 Ultralytics YOLOv8s 模型，将模型 17 类原始输出映射为 person、mask、gloves、lab_coat、goggles、helmet 六个系统业务类别。

**视频处理层**（video/processor.py）：以 InspectionPipeline 类组织完整检测管线，负责视频抽帧、逐帧检测、违规截图保存与统计汇总。

**规则判断层**（rule_engine/engine.py）：独立规则引擎，输入"已穿戴 PPE 集合 + 区域必需 PPE 集合"，输出违规评估结果与缺失项明细。

**数据存储层**：SQLite（backend/database.py），含 laboratories（实验室）、areas（区域）、safety_rules（规则）、detection_records（检测记录）、violation_events（违规事件）五张业务表。

分层设计使模型、规则、存储相互解耦——后续替换检测模型时，只要保持检测输出结构不变，其他模块无需改动。

## 7. AI 技术方案

### 7.1 模型、类别与匹配方法

系统当前实际使用的检测模型为基于 SH17 数据集训练的 YOLOv8s 开源权重（22.5MB）。SH17 是面向工业场景人员安全与 PPE 检测的公开数据集（8,099 张图片、17 类，arXiv:2407.04590）。模型输出经类别映射转换为六个系统业务类别：person（人员）、mask（口罩）、gloves（手套）、lab_coat（实验服）、goggles（护目镜）、helmet（安全帽）。

人员与 PPE 的关联采用空间归属匹配（ai/ppe_matcher.py）：将每个 PPE 检测框按空间位置归属于相应人员框，得到"每人实际穿戴的 PPE 集合"，避免多人同框时张冠李戴。ROI 判断（ai/roi.py）以人员检测框中心点是否落入区域矩形为依据，只有进入实验操作区域的人员才按该区域规则评估。

系统默认安全规则为：实验操作区域内人员须佩戴口罩、手套、实验服；缺失 1 项为一般违规，缺失 2 项及以上为严重违规，穿戴齐全为正常。规则存储于数据库 safety_rules 表，可按区域在系统设置页调整，而非硬编码。护目镜、安全帽当前未列入默认必需项。

### 7.2 模型优化实验与当前状态

SH17 属工业制造场景数据集，其"实验服"类别（medical-suit / safety-suit，视觉上以连体防护服为主）与实验室白大褂存在明显差异。为此，开发团队在系统之外建立了独立的模型实验体系（E1~E4），使用公开数据集开展再训练与评估：

**基线模型（当前生产使用）**：SH17 YOLOv8s，数据集发布方公开的验证集指标 mAP@50 = 63.7（引自公开数据，非本项目实测）。

**实验模型（E2 训练完成，尚未接入生产）**：使用公开 LAB_PPE 数据集（Roboflow，7,401 张，经类别整理与去重检查）训练的 YOLOv8s（50 epochs）。同分布测试集上 4 类 PPE 整体 mAP@50 = 0.928，其中实验服 F1 = 0.952，明显优于基线。

**外部测试（E3）**：在独立保留、与训练数据零重叠的真实实验室照片集（251 张）上对比：实验模型 4 类 PPE mAP@50 为 0.438，高于基线的 0.364；口罩 F1 由 56.5 提升至 75.1，实验服 F1 由 15.9 提升至 34.0（约 2.1 倍），手套基本持平（78.5 对 75.7），护目镜有所下降（49.8 对 32.7）；人员检测由 SH17 模型负责，F1 为 95.8。

**当前结论与技术挑战**：实验模型在真实实验室照片上实验服识别仍不理想（F1 = 0.34），存在明显领域差异——公开数据中的实验服图像多为摆拍风格，与真实实验室场景在视角、光照、人员尺度上差异较大，部分真实白大褂照片模型完全未检出。为此团队已制定实验服定向优化方案（E4）：已完成一个公开实验服数据集（476 张）的下载与去重审计，计划与自采数据一起定向增训，该训练尚未启动；同时也在评估"按类别混合路由"的接入方案（人员、护目镜由 SH17 负责，口罩、手套、实验服由实验模型负责）。上述指标均完整记录于项目实验报告（docs/E1~E4 系列），实验遵循"外部测试数据永不参与训练"原则；模型优化仍是进行中的工作，当前系统演示使用 SH17 基线模型。

## 8. 项目创新点与特色

本项目的特色主要体现在系统设计层面：

**检测结果与业务规则的深度结合**。项目没有停留在"识别出目标"的层面，而是设计了从检测结果到违规事件的完整转换链路：先做人员与 PPE 的关联，再叠加区域与规则判断，最终生成具有明确业务含义的违规事件（谁、在哪个区域、缺了什么、严重程度如何）。

**实验操作区域 ROI 机制**。只有进入实验操作区域的人员才按该区域规则评估，避免"全画面一刀切"的误报，使判断逻辑贴近真实实验室管理场景。

**规则可配置**。必需 PPE 清单按区域存储于数据库，可在系统设置中调整，使系统能适应不同实验区域的管理要求。

**从目标识别到事件闭环**。系统自动保存违规截图、记录事件、支持按时间与类型的查询统计，形成"检测—预警—记录—统计"完整闭环。

**规范的工程实践**。项目建立了 Git 多分支协作流程、接口契约文档、14 个用例的系统测试集以及独立的模型实验评估体系，协作与实验记录均可追溯。

## 9. 项目应用场景

本项目面向需要进行实验人员 PPE 穿戴规范检查的场景，包括高校教学实验室、科研实验室及其他对人员防护有明确要求的实验区域。典型使用方式为：对实验区域的摄像画面（或离线录像）进行持续或定期的自动巡检，检测到进入实验操作区域的人员缺失必需防护装备时，生成违规记录并留存截图，供安全管理人员查阅与统计。

需要强调，系统定位为**辅助巡检与违规预警工具**：它可以在无人值守时持续检查、自动记录、汇总统计，但违规的最终认定与处置仍需管理人员介入；系统针对的是视觉可识别的 PPE 穿戴违规，不涉及消防安全、气体监测、人员行为冲突等其他安全管理领域。

## 13. 项目风险与限制

**数据集领域差异**：公开 PPE 数据集多为摆拍或工业场景图像，与真实实验室场景在光照、视角、人员尺度、着装风格上差异明显，模型跨数据集泛化受限——E3 外部测试已有定量体现（实验服 F1 仅 0.34）。这是当前最主要的技术风险，也是 E4 优化的直接目标。

**类别语义近似**：SH17 无独立"实验服"类别，系统当前将 medical-suit / safety-suit 映射为 lab_coat 属近似处理，可能把连体防护服判定为实验服；团队已明确"连体防护服不等同于实验服"的业务边界，将在模型定型接入时统一修订映射。

**环境因素影响**：拍摄角度、距离、光照、遮挡会影响检测效果；护目镜等小目标在部分场景下识别偏弱。

**检测范围限制**：系统仅判断 PPE 是否穿戴，无法判断是否规范穿戴（如口罩是否遮住口鼻），不涉及化学品泄漏、烟雾等非视觉或非 PPE 类安全问题。

**项目性质限制**：本项目为课程原型系统，未经过真实实验室环境长期运行验证，不等同于生产级监管系统；违规最终认定仍需人工复核。

## 14. 总结

本项目围绕"实验操作区域人员 PPE 穿戴合规性巡检"这一明确需求，采用开源目标检测模型二次开发与系统集成的技术路线，设计并实现了覆盖"目标检测—人员与 PPE 关联—区域判断—规则判断—违规事件生成与记录—数据统计展示"完整链路的实验室安全智能巡检原型系统。系统已实现图片与视频检测、可配置安全规则、违规记录与截图、数据统计等核心功能并通过系统测试验证。在模型层面，团队基于公开数据集完成了再训练与独立对比评估，客观识别出实验服识别的跨域泛化问题并制定了定向优化方案。后续团队将按分工计划继续推进模型优化与功能完善，最终交付可运行、可演示、文档完整的课程项目成果。
