## 1. 为什么不能只改映射（关键结论）

现状 `ai/detector.py: CLASS_ALIAS` 两处映射：

```python
"medical-suit": "lab_coat",
"safety-suit": "lab_coat",
```

**但改这两行对当前系统零效果**，原因：

| 模型 | 类别名 | 是否经过这两行映射 |
|---|---|---|
| `labppe_v8s.pt`（**当前默认**） | `person/mask/gloves/lab_coat/goggles` | ❌ **不经过**——它直接输出 `lab_coat` |
| `sh17_yolov8s.pt`（回退） | 含 `medical-suit`/`safety-suit` | ✅ 经过 |

而**当前默认模型是 5 类自制模型**，它只有一个 `lab_coat` 输出类，没有区分白大褂与连体服的表达能力。

> **结论：要真正区分二者，必须新增 `coverall` 类并重训。**

## 1.1 ⚠️ 修正：连体防护服实际**不在**当前训练集中（重要）

初版分析依据 manifest 得出「lab_coat 混入 366 个 Coverall 框」，**逐层核对后发现该推断不成立**，实际数据链如下：

### 事实核对结果

| 检查项 | 结果 |
|---|---|
| 当前标签文件真实类别分布 | person 3340 / mask 1125 / gloves 2592 / **lab_coat 2463** / goggles 1416，共 10936 |
| `manifest` 中 `Coverall` 记录 | 1522 条，分两个来源 |
| └ `dataset1` 的 Coverall（783 张图 / 1156 框） | `drop_class` **已丢弃**，且这些图的标签文件**不在** `data/lab_ppe/labels/` 中（前 50 张只有 1 张存在） |
| └ `ppedetect` 的 Coverall（366 框） | 标记为 `keep`/`patch` → lab_coat，但 **`ppedetect` 与当前标签集的图片交集 = 0**，即**这批图根本没进训练集** |
| 原始 `data/raw/ppedetect` | 完整保留 402 个 Coverall 框、329 个标签文件（**但未纳入训练**） |

### 由此得出的三条重要修正

1. **当前 `lab_coat` 的 2463 框全部来自白大褂类数据**（`dataset1` 的 "Lab coat"/"lab coat" 1035+661，`labcoat_si` 304），**不含连体防护服**。
   → 因此「模型把连体服当白大褂」不是标签污染造成的，而是**纯召回问题**：模型没见过连体服，检不出，于是既不判 lab_coat 也不判其他。
2. **`dataset1` 的 1156 个 Coverall 框是被主动丢弃的**——这批图带 `mask/gloves/goggles` 标注但 Coverall 框被丢，说明当时判定其 Coverall 形态不适合作为 lab_coat。
3. **`data/raw/ppedetect` 是一份「已下载但未接入」的现成数据**：402 个 Coverall 框 + 394 个 Mask + 473 Gloves + 169 Goggles + 158 Face_Shield，**这是新增 coverall 类最直接的数据来源**。

> **这反而是好消息**：不需要从既有 lab_coat 里"剥离"任何框（无污染），只需要**新增** coverall 类 + 用现成的 ppedetect 数据填充。

## 2. 数据基础：`data/raw/ppedetect` 是现成的 coverall 数据源

勘察发现 `data/raw/ppedetect/` 目录**完整保留且未接入训练**，其 `data.yaml` 类别定义：

```yaml
names: [Coverall, Face_Shield, Gloves, Goggles, Mask]
nc: 5
```

原始标签统计（364 个标签文件）：

| 原始类 | 框数 | 对应新体系 |
|---|---|---|
| **Coverall** | **402** | → **class 5 coverall（新增）** |
| Face_Shield | 158 | → 丢弃（非系统类） |
| Gloves | 473 | → class 2 gloves |
| Goggles | 169 | → class 4 goggles |
| Mask | 394 | → class 1 mask |

**这 402 个 Coverall 框是「连体防护服」这一概念在项目里唯一的一手标注来源**，且坐标完整，**无需重新标注**。

> ⚠️ **数量评估**：402 框作为新类偏少（对比 lab_coat 2463 框、goggles 1416 框）。
> 参照经验，小类 F1 预计 **55~70%**。若要提升，需再补充连体防护服图源（见 §7 待确认事项）。

## 3. 目标类别体系（新 6 类）

```yaml
nc: 6
names:
  0: person
  1: mask
  2: gloves
  3: lab_coat      # 敞开式白大褂
  4: goggles
  5: coverall      # 新增：连体防护服
```

同步改动点：

| 文件 | 改动 |
|---|---|
| `data/lab_ppe/data.yaml` | `nc: 5` → `6`，增 `5: coverall` |
| `ai/detector.py` `SYSTEM_CLASSES` | 增 `"coverall"` |
| `ai/detector.py` `CLASS_CN` | 增 `"coverall": "连体防护服"` |
| `ai/detector.py` `CLASS_ALIAS` | `"medical-suit": "coverall"`、`"safety-suit": "coverall"`（**从 lab_coat 改指 coverall**） |
| `ai/detector.py` **`map_class()` 兜底** | ⚠️ **必须改**：现有 `if "suit" in key or "coat" in key: return "lab_coat"` 会把 `coverall` 也吞成 lab_coat。需在兜底前加 `if "coverall" in key: return "coverall"` |
| `backend/config.py` | `ALLOWED_PPE` 是否含 coverall 视业务定（**建议不含**——coverall 是「不满足 lab_coat」的证据，不是独立合格 PPE） |
| `rule_engine/engine.py` | 无需改：连体服不计入 lab_coat → 自动产生「未穿实验服」违规 |

## 5. 影响预测

### 5.1 预期指标变化

| 类别 | 预期 |
|---|---|
| **coverall（新）** | 从 0 起步。训练框数约 366，属小类，F1 预计 60~75%（参照 lab_coat 的 85.4% 与 gloves 的 74.1%） |
| **lab_coat** | 拆出 366 个 Coverall 框后，正样本更纯（不再混入连体服），**F1 可能小幅上升** |
| person / mask / gloves / goggles | 基本不变（标签未动） |

### 5.2 业务行为变化

| 场景 | 现在（Route A） | 改后（Route B'） |
|---|---|---|
| 穿敞开式白大褂 | ✅ 合规 | ✅ 合规（不变） |
| 穿连体防护服 | ✅ 判为已穿实验服 | ⚠️ **判「未穿实验服」** |
| 医用防护服 4 人图（`img_6960cb81.jpg`） | 报 3 人 + 全判未穿实验服（因召回=0） | 报 4 人 + coverall 检出 + 判未穿实验服（**判定一致，但归因变清晰**） |
| CDC t06 连体服图 | 一般违规（缺口罩） | **严重违规（缺实验服 + 缺口罩）** |

> ⚠️ **需确认**：t06 类场景「全副武装的防疫人员」被判「严重违规（未穿实验服）」是否符合你们的业务预期？若该场景算合规，则需在规则层为 coverall 增加豁免配置。

### 5.3 风险评估

| 风险 | 说明 | 缓解 |
|---|---|---|
| **IoU 匹配误伤** | 同图内真正的 lab_coat 框被误改为 coverall | 阈值取 0.9 并输出匹配报告人工抽查 |
| **coverall 小类欠拟合** | 366 框训练量偏小 | 从 `data/raw/ppedetect` 补齐 36 个未录入框；考虑负样本增强 |
| **测试集口径不一致** | test split 有 48+104 张涉 Coverall，GT 未区分 | 重训前需同步修正 test 标签，否则评估指标失真 |
| **与既定文档冲突** | E4 决策文档写明 Route A | 本文档即为其**正式推翻记录**，需在 E4 文档加「已作废」标注 |
