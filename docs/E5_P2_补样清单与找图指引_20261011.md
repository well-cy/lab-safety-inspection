## 0. 为什么补、补什么（一句话版）

E4 重训为补齐 lab_coat，把模型容量大幅拉向该类，代价是 **gloves / goggles 跨域 F1 回退**：

| 类别 | E4 重训前（SH17 参照） | E4 重训后（当前网模型） | 变化 | 目标 |
|---|---|---|---|---|
| **goggles** | 0.498 | **0.221** | −27.7 pt | **全类最大短板**，优先 |
| **gloves** | 0.785 | **0.649** | −13.6 pt | 翻回 0.75+ |

> 数据来源：dataset2 external_test（251 张）重跑 E3，见 `docs/E3_retest_20261011.md` §2。
> 结论：这两个类别**不能再从现有库里捞**，必须定向补新图（详见 §2 可达性）。

**本轮目标量（对齐 E5 §3 P0' 第 8/9 条）**

| 目标 | 量 | 验收 |
|---|---|---|
| goggles 正样本 | **+300 ~ 500 框** | goggles 跨域 F1 ≥ 0.45（先回到 SH17 水平，再谈超越） |
| gloves 正样本 | **+300 ~ 500 框** | gloves 跨域 F1 ≥ 0.75 |
| 眼镜类负样本（配套） | +200 ~ 300 张 | 抑制「眼镜→护目镜」误检，保护 goggles 精确率 |

## 3. 采集指引

### 3.1 路径 A — 外部库搜图与准入（判据「五问」）

搜图关键词建议（Roboflow Universe / Kaggle / Hugging Face Datasets）：

- goggles：`safety goggles detection`、`eye protection detection`、`ppe goggles`、`实验室 护目镜`
- gloves：`safety gloves detection`、`nitrile gloves detection`、`surgical gloves detection`

**每库必过「五问」，任一不过就整库弃用（省得白标）：**

1. **域名对不对？** 必须是**实验室 / 科研 / 医疗操作**场景。影棚摆拍、商场人群、街景、生活照、webcam 车间 —— 一律不要。
2. **和红线撞不撞？** 跑 `tools/crosslib_phash.py --thr 0`，对 `data/lab_ppe`（train+valid）**和** dataset2（test 红线）双向查。命中即剔。
3. **和旧库重不重？** 同上对比 `dataset1` / `ppes-kaxsi` / `safety-gloves` —— 这 5 个库已入库，同源副本必须去（参考 `tools/cluster_phash_list.py`、`tools/dupcheck_orb_list.py`）。
4. **类别映射对不对？** 源类别只允许映射到 `gloves(2)` / `goggles(4)`；同图内若有 `mask`/`lab_coat` 可一并映射（避免无标注正样本压制）；`no_gloves`/`helmet`/`shoes` 等**框丢弃、图保留为背景负样本**。
5. **够不够用？** 去重后**正样本框 ≥ 80** 才值得写入库脚本；否则并入路径 B 一起做。

**入库工具模板**：照 `tools/merge_sglasses_proj.py`（干跑 / `--apply` / 前缀隔离 / 可整体回滚）或 `tools/merge_glove_datasets.py`。**前缀必须唯一**（如 `sgx_`、`glx_`），便于消融与回滚。

### 3.2 路径 B — 自采集实拍（SOP 见 `docs/B1_采集SOP.md`）

沿用既有硬约束，**不要另起一套**：

- **拍摄矩阵**：≥3 人、≥3 种光照（顶灯 / 侧光 / 逆光）、近 / 中 / 远三距离 —— 照 B1 §1 的 150 张构成凑数。
- **goggles 重点形态**（治 0.221 短板）：透明镜片正面对光、侧面 45°、深框 / 浅框 / 无框、戴在额头上、卡在鼻梁下半戴、与普通眼镜**同框对照**。
- **gloves 重点形态**（治 0.649 回退）：**白手套**（配白大褂，同色低对比）、蓝丁腈、深色、**袖口遮挡**、画面底边只露半只、持器械手、交叉抱臂手。
- **技术规范**：手机原图直出，**不要**开美颜 / 滤镜 / 数码变焦；横竖都拍；文件名按 B1 §4 命名。
- ⚠️ **B1 §110 可行性状态**：先读那段确认当前实拍条件是否满足（人力 / 场地 / 设备），别默认能做。

### 3.3 负样本（配套，P1 类）

| 场景 | 量 | 治什么 |
|---|---|---|
| 普通近视镜（不戴护目镜） | +200 ~ 300 张 | 「眼镜→护目镜」误检（全图 0.61，几何不可分） —— **保护 goggles 精确率**，必配 |
| 裸手入镜（持器械 / 交叉 / 叉腰）、白鞋、白大褂衣料特写 | +200 张 | 手套 FP 家族（0.45 ~ 0.87） |
| 玻璃台面 / 反光地面 | +50 ~ 100 张 | 倒影手套 FP（代码过滤治标，数据治本） |

> 负样本**不标框**（或只标真目标），随图入库即可 —— 空标签图即背景负样本，这是已有惯例。

## 4. 入库四关（对齐 E5 §3 末段，逐关留痕）

1. **红线去重**：`tools/crosslib_phash.py --thr 0`，对 train/valid **与** dataset2(external_test) 双向。
2. **库内近重复**：pHash 聚类（`tools/cluster_phash_list.py`）+ ORB 同源（`tools/dupcheck_orb_list.py`）。
3. **脏图筛查**：空标签 / 越界框 / 全黑全白 / 纯 logo 图。
4. **标注一致性审计**：同源副本一致率、相邻帧翻转率、类别定义域匹配。

**入库落点硬规则**（红线，见 E4 规划）：

- 新增数据 **只进 train / valid，绝不进 test**；源库的 test 图一律**改入 train**。
- 每关产出报告落 `data/*_report.txt`，抽检图版落 `outputs/<name>_review/`。
- 入库后**立即**用「tar 备份 vs 磁盘逐图差分」算净增量，写 `docs/E4_lab_coat_plan.md` 的 B+NN 小节。
- **B+NN 撞号**：追加前 `grep -n '^### B+' docs/E4_lab_coat_plan.md` 确认下一号（person / lc13 两线交替占用）。

## 5. 执行顺序（关键，顺序错了重训白跑）

```
① lc13 剩余全部审完落库      ← 527 张（train 392 / val 135），当前进行中
       │   （必须先完成，否则这批 lab_coat 进不了本次重训）
       ▼
② P2 找图 / 实拍 + 四关入库   ← 本清单的活
       │
       ▼
③ 离线增广（E5 §4，脚本可跑）
       │
       ▼
④ 一次重训（P2 目标模型）
       │
       ▼
⑤ E3 复测 → 对照本清单 §0 的验收线
```

> **为什么 ① 必须在 ④ 之前**：重训是全量重跑。若 lc13 还没审完就重训，那 527 张 lab_coat 等于没进训练集，
> 重训完还得再跑一轮 —— 白烧算力（V100 ≈ 2 点/小时，一轮 5~7 点）。
> **②③ 与 ① 可并行**（找图不占算力），但**入库落库**建议排在 ① 之后，避免两线同时写 `data/lab_ppe` 时
> 净增量口径被污染（三线并行时更乱）。
